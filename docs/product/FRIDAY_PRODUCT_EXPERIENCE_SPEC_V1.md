# Friday Product Experience V1

**Owner contract, 2026-09-29.** UX-60A establishes the product shell. Dynamic Learning Paths owner controls were integrated afterward; this does not qualify matrix row 60 or accept the final visual design.

## Product model

**NeetCode-style product discipline + Astra Ultra Friday presence.** The current public NeetCode product is a major visual and interaction reference for learning navigation, roadmap scanning, practice lists, course structure, progress and restrained dark surfaces; see `NEETCODE_UX_REFERENCE.md`. Friday's implementation, content, data and identity remain original. The accepted Astra Ultra `NeuralPresence.tsx` brain is a protected design asset: retain its geometry, materials, shader behavior, animation and cognitive-state response. Home gives that brain room while keeping the canonical Conversation immediately useful.

**Complex backend. Simple surface. Deep details on demand.** Friday is the product identity. Career Forge remains the canonical learning engine and is called **Learn** in normal UI. The default surface shows the owner's task, Friday's current work, real attention, evidence-based progress, next actions, readable history, and results. Technical IDs, hashes, workers, service details, and qualification terminology belong under Settings → Advanced → Developer / Diagnostics or explicit technical disclosure.

The persistent desktop navigation is Home, Learn, Projects, Knowledge, Automate, History, with Notifications and Settings as global utilities. Home owns the main canonical Conversation and composer. Ask Friday from any workspace returns to that same runtime session. Context from an arbitrary workspace must only be attached through a future typed protocol; navigation alone does not imply such attachment. Legacy deep routes remain deliberate entry points.

Learn contains Overview, Roadmap, Practice, Interview, and Progress. The current roadmap presents only the canonical Career Forge competencies and mastery, with a direct route into the current mission; it does not fabricate DLP nodes. Projects projects the existing Career Forge learning-project service and does not imply a general project engine. Knowledge joins Research with selected private indexed knowledge while preserving source and evidence authority. Automate shows existing Objectives, Activity, Notifications, and watch state; no watch creation or scheduling control is implied. History shows human-readable outcomes before technical objects. Settings contains Personalization & Memory, Privacy & Perception, and Advanced diagnostics. Notifications use canonical backend state and existing desktop attention; no browser-local notification authority is created.

All durable conversation, memory, learning, research, task, event, capability, desktop, and system state stays with its current canonical service. The browser may hold only transient presentation state such as route, form draft, filters, and expanded details. Learning progress requires real Career Forge evidence; no seeded progress or browser-authored mastery is allowed.

## Visual and interaction contract

Dark-first, neutral surfaces, high-contrast text, restrained accent, and semantic success/warning/danger. Color never carries a state alone. Friday Sans is a local identity font; normal reading uses a local system sans stack. No CDN fonts, remote icons, remote CSS, or analytics are required to load the shell offline. Body text targets 16px, secondary text 14px, long-form lessons 17–18px, card titles 17–18px, section headings 22–24px, page headings 30–36px, and long-form line height 1.6–1.7 within roughly 760–840px. Normal owner information must not rely on 7–10px labels.

Navigation uses semantic landmarks, visible active and focus states, labels, keyboard access, and reduced-motion support. Ctrl/Cmd+K is navigation search, never arbitrary command execution. Narrow windows preserve legibility and avoid ordinary-page overflow. Owner summaries appear first; evidence and technical details are disclosed deliberately.

## Dynamic Learning Paths owner integration

Dynamic Learning Paths is a first-class curriculum-sequencing capability above
Career Forge. DLP-1 through DLP-4 are accepted and published. Learn provides
functional path selection, sequencing, review delivery/answer submission, and
reinforcement handoffs for supported fixed and dynamic subjects. Career Forge
remains the authority for attempts, assistance, assessment, evidence, mastery,
retention, and reinforcement; the browser does not author answers to memory or
calculate mastery/sequencing. Row 61 remains PARTIAL for manual curriculum
editing, project/capstone lifecycle integration, cross-path evidence reuse,
major adaptive replanning, broader owner qualification, and final visual design.
The current Learn UI is a FUNCTIONAL INTEGRATION SHELL. Final visual acceptance
has not been owner accepted and redesign is deferred until the capability stack
is complete.

Matrix row 60 tracks whole-product experience completeness and remains **PARTIAL** after UX-60A and DLP-2. Dynamic Learning Paths has independent capability tracking in row 61 because it introduces new persisted learning authority and qualification distinct from navigation or shell completeness.
